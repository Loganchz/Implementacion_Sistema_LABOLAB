# Bitácora de Desarrollo - Labolab LIMS
**Fecha:** 7 de octubre de 2026  
**Objetivo principal:** Independización de servicios externos (Abacus.AI), implementación de generación local de PDFs con Puppeteer/Chromium, sincronización con repositorio GitHub y levantamiento del entorno de desarrollo.

---

## 1. Contexto para Desarrolladores e Inteligencias Artificiales

Este proyecto es **Labolab LIMS**, un sistema de gestión para laboratorios de análisis de alimentos y aguas en Quito, Ecuador (acreditado bajo norma NTE INEN / ISO/IEC 17025:2018).

- **Stack:** Next.js 14 (App Router) + React 18 + TypeScript + Prisma 6 + PostgreSQL + Tailwind CSS + shadcn/ui.
- **Entorno:** Docker Compose (`db` con Postgres 16 Alpine, `app` con Node 20 Bookworm).
- **Repositorio oficial:** `https://github.com/Loganchz/LABOLAB---LIM.git` (rama `main`).
- **Línea base previa:** El proyecto se encontraba originalmente configurado para depender de una API propietaria externa (`apps.abacus.ai`) para generar PDFs e inyectaba scripts de chat. Esa dependencia causaba fallos al no tener credenciales externas y filtraba datos a terceros.

## 3. Detalle de Cambios Técnicos

### 3.1. Motor Local de PDFs (`lib/pdf.ts`)
- **Qué se hizo:** Se creó el archivo [`lib/pdf.ts`](file:///c:/Users/pc/Desktop/LIM/labolab-lims/lib/pdf.ts) que inicializa `puppeteer-core` apuntando a Chromium (`/usr/bin/chromium` en Linux/Docker o rutas estándar de Chrome/Edge en Windows). Maneja un almacén en memoria (`pdfStore`) con identificador único `request_id` y limpieza automática de memoria (TTL 30 min).
- **Por qué:** Antes, las rutas llamaban a `https://apps.abacus.ai/api/createConvertHtmlToPdfRequest`. Al no tener API Key, Abacus devolvía `403 Forbidden ("User not logged in")`, provocando un error 500 en la app y haciendo imposible descargar documentos.
- **Para qué:**
  - Garantizar **100% de autonomía**: el sistema funciona sin internet y sin suscripciones a APIs externas.
  - Preservar la **confidencialidad médica/industrial**: los datos de clientes, muestras y resultados nunca salen de la infraestructura de Labolab.
  - Reducir el tiempo de respuesta a menos de un segundo por PDF.
  - **Mantener intacto el diseño visual**: el HTML y CSS existentes en las plantillas se renderizan con exacta fidelidad.

### 3.2. Adaptación de Endpoints de PDF
- **Archivos modificados:**
  - `app/api/quotes/[id]/pdf/route.ts` (Proformas / Cotizaciones)
  - `app/api/work-orders/[id]/pdf/route.ts` (Órdenes de Trabajo)
  - `app/api/reports/[id]/pdf/route.ts` (Informes de Ensayo con QR)
  - `app/api/generate-pdf/route.ts` (Endpoint general de conversión)
  - `app/api/generate-pdf/status/route.ts` (Polling de estado)
- **Qué se hizo:** Se reemplazó el `fetch` externo por llamadas a `createLocalPdfJob()` y `getPdfStatus()` de `lib/pdf.ts`.
- **Por qué:** Para conectar el backend existente directamente con el nuevo motor local sin alterar los contratos con el frontend.
- **Para qué:** El frontend sigue haciendo el mismo flujo (`POST` al endpoint del documento y posterior lectura del `status`), por lo que no hubo que modificar los componentes de descarga en las vistas.

### 3.3. Configuración del Contenedor Docker (`Dockerfile` y `docker-compose.yml`)
- **Qué se hizo:**
  - Se añadieron los paquetes del sistema `chromium`, `fonts-liberation` y `fonts-dejavu-core` al `Dockerfile`.
  - Se agregaron las variables `PUPPETEER_EXECUTABLE_PATH=/usr/bin/chromium` y `PUPPETEER_SKIP_CHROMIUM_DOWNLOAD=true`.
  - Se eliminó la variable obsoleta `ABACUSAI_API_KEY` de `docker-compose.yml`, `.env` y `.env.example`.
- **Por qué:** El contenedor base (`node:20-bookworm-slim`) no contaba con los binarios de Chromium ni las fuentes tipográficas necesarias para renderizar PDFs.
- **Para qué:** Lograr que cualquier desarrollador que clone el repositorio y ejecute `docker compose up --build` tenga el generador de PDFs funcionando de inmediato sin instalaciones adicionales.

### 3.4. Eliminación de Rastros de Abacus.AI
- **En `app/layout.tsx`:** Se removió `<script src="https://apps.abacus.ai/chatllm/appllm-lib.js" />`.
  - *Motivo:* Era un widget de chat de la plataforma cloud original que generaba llamadas fallidas en consola.
- **En `scripts/seed.ts`:** Se removió la creación del usuario de prueba `abacus-b9c39a5e@example.com`.
  - *Motivo:* Usuario administrativo fantasma innecesario en producción.
- **En `README.md`:** Se actualizó la tabla de variables y la documentación técnica para aclarar que la app no requiere claves de IA y genera PDFs localmente.

### 3.5. Generación de QR Local (`app/(dashboard)/reportes/[id]/page.tsx`)
- **Qué se hizo:** Se implementó `QRCode.toDataURL()` utilizando la biblioteca `qrcode` ya presente en el proyecto.
- **Por qué:** La vista previa del informe en pantalla utilizaba una URL externa (`api.qrserver.com`), lo que fallaba sin conexión a internet o ante bloqueos de red.
- **Para qué:** Que la vista previa en el navegador también sea 100% autónoma y no dependa de servidores externos.
